# 비비수산 분석 결과와 화면 연동 기준

> 2026-10-23 폴더 재편 전 문서입니다. 안의 경로(01_~08_ 등)와 방식은 예전 기준이고, 지금 흐름은 맨 위 README.md를 보세요.

대시보드의 구성과 화면 구현은 별도 담당자가 맡는다. 분석 담당자는 모델·상품 통계·근거 리뷰를 전달하고, 화면 담당자는 이를 AI 지식이 없는 사용자도 이해할 수 있는 흐름으로 제공한다. 아래는 연동 기준이며 화면 개발을 분석 착수 전에 수행할 필요는 없다.

2026-10-16에 [실제 DB·인증 API 백본](../docs/local-backbone-pilot.md)을 구현했다. 사용자는 여러 직원의 사내 웹 접근 방식을 선택했다. `/api/products`, `/api/reviews`, `/api/uploads`, `/api/uploads/{job_id}`, `/api/summary`를 연결할 수 있다. 로그인 화면·계정별 권한·TLS·사내 배포는 후속이다. 별점 기초통계는 전체 데이터와 대조했지만 6상품 로컬 모델은 운영 품질 미달이라 자동 분석을 기본 비활성으로 두었다. 자료 반영 성공·분석 비활성·분석 오류·미분류를 서로 다른 상태로 표시해야 한다.

## 분석 담당 범위

분석 담당자는 원본 정제, 정답 레이블 준비, BERT 속성·감성 분류, 임베딩과 토픽 탐색, 기간별 상품 통계, 근거를 포함한 요약, 신규·수정 리뷰 처리를 맡는다. 처음에는 로컬 Parquet·CSV·JSONL로 작업하고 결과 형식이 안정되면 DB와 API로 연결한다.

## 결과에 포함할 정보

| 결과 | 필수 정보 |
| --- | --- |
| 리뷰별 분석 | 상품번호, 리뷰 ID, 작성일, 유형, 별점, 속성, 감성, 의견 근거, 분석 상태, 모델 버전 |
| 상품별 통계 | 기간, 리뷰 유형, 전시 범위, 리뷰 건수, 평균 별점, 분석 완료 건수, 속성·불만 건수와 분모 |
| 세부 불만 | 검수된 이름, 업무용 토픽 ID, 토픽 버전, 발생 건수, 근거 리뷰 ID |
| 변화 요약 | 비교 기간, 변화량과 표본, 관측 내용, 관련 의견, 가능한 설명, 확인할 사항, 근거 ID |
| 데이터 반영 | 반영 범위와 기준 시각, 신규·수정·미변경·오류 건수, 분석 진행 상태 |

AI 분석 전이나 자료가 부족한 경우 상태를 명시한다. 불만 0건으로 전달하지 않는다. 원문에 접근할 수 있는 사용자 범위를 적용하고 블라인드 리뷰와 비공개 필드를 일반 결과에 섞지 않는다. 모델 점수는 검증한 종류와 의미를 전달하며 정확할 확률이라고 단정하지 않는다.

## 사용자가 이해할 표현

일반 화면에는 모델 이름과 군집 번호 대신 맛·신선도·배송, 좋은 의견·아쉬운 의견, 배송 지연·해동 도착처럼 익숙한 표현을 쓴다. 비율의 분자·분모, 선택 기간, 실제 근거 리뷰를 확인할 수 있어야 한다. 낮은 확신과 속성 미언급, 의견 중립을 구분한다.

추천할 작업 흐름은 상품 상태 확인, 고객 의견 조회, 파일 업데이트 세 가지다. 메뉴 수와 실제 화면 구성은 대시보드 담당자가 확정한다. 기간과 상품 선택 상태를 유지하고 근거 리뷰에서 되돌아올 때 기존 상태를 복원하는 흐름을 검토한다.

요약의 원인 추정과 관측된 변화를 구분한다. 리뷰 수를 판매량이나 매출로 표시하지 않는다. 화면의 쉬운 말과 모델의 오류 검증은 각각 필요하다.

## 연동 순서

1. 대표 상품의 실제 통계와 결과 스키마를 공유한다.
2. 각 분석 단계가 준비되는 대로 상태·근거를 포함한 실제 결과 파일을 전달한다.
3. 화면의 상품·기간·의견 필터에 필요한 조회 계약을 협의한다.
4. 운영 규모와 저장 방식이 정해지면 DB·API로 연결한다.

실험 모델의 시험 10건 예측은 있으나 운영 품질은 확보되지 않았다. 상품 전체의 속성·불만 집계는 아직 없다. 화면에 예시나 실험 결과를 사용한다면 운영 분석과 구분해야 한다.
