# 검수 기준 한 장 요약 (치즈스틱 50건)

검수 화면 옆에 띄워 두고 보는 요약입니다. 자세한 설명은 [사용 가이드](pilot_products/296889036/data/opinion_review_v1/annotation-guide.md)에 있습니다.

**핵심 한 줄:** 고객이 **무엇을(속성) · 좋다/나쁘다(감성) · 왜(이유)** 말했는지, **원문 구절 그대로** 근거를 붙인다. 리뷰에 없는 내용은 추측해서 채우지 않는다.

## 1. 한 리뷰 처리 순서

1. 리뷰 전체를 읽는다. **별점은 정답이 아니다.** 5점 리뷰에도 불만이 있고 1점 리뷰에도 칭찬이 있다.
2. AI 초안 의견을 하나씩 확인한다. 틀리면 고치고, 없는 의견은 추가하고, 원문에 없는 의견은 지운다.
3. 의견이 더 없는지 리뷰를 한 번 더 읽는다.
4. 리뷰 판정을 고르고 **검수 완료**를 누른다. 애매하면 메모를 남기고 **보류**한다.
5. 끝날 때마다 **JSON 내보내기**로 저장한다.

## 2. 의견은 어떻게 나누나

**속성·감성·이유가 하나라도 다르면 의견을 따로 만든다.**

> 예: "치즈가 고소하고 맛있는데, 생각보다 잘 안 늘어나고 튀김옷도 너무 두꺼워요"
> → ① 맛 · 긍정 · 치즈 풍미 ② 식감 · 부정 · 치즈 늘어남 ③ 재료 구성 · 부정 · 튀김옷 비율 (의견 3개)

> 예: "배송도 빠르고 포장도 꼼꼼해요" → 배송 · 긍정, 포장 · 긍정 (의견 2개)

## 3. 속성 고르기

| 속성 | 넣는 것 | 넣지 않는 것 |
| --- | --- | --- |
| **맛·냄새** `taste` | 맛있음, 짜다·싱겁다, 밀가루 맛, 치즈 풍미, 이상한 냄새 | 늘어남·바삭함 같은 물성 → 식감 |
| **식감** `texture` | 안 늘어남, 쫀득, 바삭, 눅눅, 딱딱, 흐물 | 맛 → 맛·냄새 / 재료 비율 → 재료 구성 |
| **재료 구성** `ingredient_composition` | 치즈가 적다·많다, 튀김옷이 두껍다 | 전체 양·크기 → 양·크기 |
| **양·크기** `quantity` | 양이 많다·적다, 크기가 작다 | "1kg 샀어요" 같은 사실 → 사실 |
| **품질·상태** `quality` | 녹아서 옴, 부서짐, 내용물 하자 | 포장재 문제 → 포장 |
| **신선도** `freshness` | "신선하다", "상했다" 처럼 직접 말한 것 | 녹은 것만으로 상했다고 판단하지 않음 |
| **배송** `delivery` | 빠르다, 늦다 | 단순 수령("잘 받았어요")은 평가로 보지 않음 → 사실 |
| **포장** `packaging` | 꼼꼼한 포장, 아이스팩·보냉 부족, 터짐 | 음식 자체 상태 → 품질 |
| **가격** `price` | 저렴, 가성비, 비싸다 | 가격 숫자·할인 구매 사실만 → 사실 |
| **조리 편의** `cooking_convenience` | 간편하다, 번거롭다, 기름 튀어서 귀찮다 | 조리 온도·시간 안내만 → 사실 |
| **조리 결과** `cooking_result` | 에어프라이어로 하니 터짐, 팬이 더 잘 됨 | 바삭함·맛만 말하면 → 식감/맛 |
| **설명 일치** `description_match` | 안내대로 했는데 안 됨, 설명과 다름 | 단순 취향 차이 |

**화면에 없는 경우**
- "좋아요", "별로예요"처럼 **무엇이 좋은지 말하지 않은 종합 평가** → 속성 `out_of_scope`(체계 밖), 메모에 `종합 만족`
- "또 살게요", "다시는 안 사요" → 속성 `out_of_scope`, 메모에 `재구매 의향`
- "아이들이 잘 먹어요"처럼 **이유 없는 반응** → 맛으로 바꾸지 말고 위와 같이 `종합 만족`
- **용도·상황 만족**("맥주 안주로 좋네요", "아이들 간식으로 딱이에요") → `종합 만족` (2026-10-19 정책)
- **원료 불신·애매한 불만**("가짜 치즈 같아요", "치즈가 싸구려인가?") → `종합 불만` (2026-10-19 정책)
- 구매 동기만 말한 문장("간식으로 샀어요")은 평가가 아니라 **사실**
- 속성이 정말 모르겠으면 `unknown`, 사실처럼 속성이 없으면 `none`

## 4. 헷갈리는 경계

| 표현 | 이렇게 |
| --- | --- |
| "치즈가 고소해요" | 맛 · 긍정 · 치즈 풍미 |
| "치즈가 안 늘어나요" | **식감** · 부정 · 치즈 늘어남 (치즈가 적다고 추측하지 않음) |
| "치즈가 너무 적어요" | **재료 구성** · 부정 · 치즈 함량 |
| "튀김옷이 두꺼워서 빵 먹는 느낌" | 재료 구성(튀김옷 비율) + 맛(밀가루 맛)으로 나눌 수 있음 |
| "녹아서 왔어요" | 품질 · 부정 · 해동 상태. 아이스팩 언급이 있으면 포장(보냉)도 따로 |
| "에어프라이어에 돌리니 다 터졌어요" | 조리 결과 · 부정 · 에어프라이어 조리 결과 |
| "쏘쏘, 그냥저냥" | 감성 **중립** |
| "먹을 만해요" | 맥락상 받아들이는 뜻이면 약한 **긍정**, 애매하면 **애매함** |

## 5. 감성 고르기

| 감성 | 언제 |
| --- | --- |
| 긍정 / 부정 | 분명할 때 |
| 혼합 | 한 구절 안에서 좋고 나쁨이 섞여 나누기 어려울 때(나눌 수 있으면 의견 2개로) |
| 중립 | 실제로 평가했는데 좋지도 나쁘지도 않다고 말할 때("보통이에요") |
| 애매함 | 평가는 있는데 방향을 판단할 수 없을 때 |
| 해당 없음 | 사실·묘사("어제 받았어요", "1kg 샀어요") |

평가가 없는 문장을 자동으로 "중립"으로 만들지 않는다.

## 6. 평가 대상

- **현재 상품** 치즈스틱에 대한 말이면 `current_product`
- **다른 상품**(같이 산 치즈볼, 예전 다른 브랜드)이면 `other_product`. **이번 상품 불만으로 옮기지 않는다.**
- 일반 취향·과거 경험이면 `general_experience`, 판단 불가면 `unclear`

## 7. 세부 이유 (화면에 있는 17개)

맞는 것이 있으면 고르고, **없으면 비워 두고 "이유 자유 서술"에 고객의 표현을 적는다.** 이유 코드는 좋다·나쁘다를 뜻하지 않는다. 감성은 따로 고른다.

| 속성 | 이유 코드 |
| --- | --- |
| 맛·냄새 | 치즈 풍미, 밀가루 맛, 간·짠맛 정도 |
| 식감 | 치즈 늘어남, 묽음·단단함, 바삭함 |
| 재료 구성 | 치즈 함량, 튀김옷 비율 |
| 양·크기 | 상품 크기, 전체 양 |
| 품질 | 해동 상태 |
| 포장 | 보냉 구성 |
| 배송 | 도착 속도 |
| 가격 | 가격 대비 가치 |
| 조리 편의 | 조리 수고 |
| 조리 결과 | 에어프라이어 조리 결과 |
| 설명 일치 | 조리 방식 안내 일치 |

짧은 칭찬("맛있어요")처럼 이유가 없으면 이유를 비워 둔다. **억지로 만들지 않는다.**

## 8. 리뷰 판정과 완료

| 판정 | 언제 |
| --- | --- |
| 의견 있음 | 평가가 하나라도 있으면 |
| 사실·묘사만 있음 | 구매·수령 사실만 있으면(사실 의견을 기록한 뒤) |
| 평가 의견 없음 | 전체를 읽었는데 기록할 것이 전혀 없을 때만 |
| 보류 | 기준이 애매하거나 의견이 갈릴 때. **메모 필수** |

- 완료한 리뷰를 고치면 다시 "작성 중"이 된다. 확인 후 다시 완료한다.
- 다 끝나면 JSON을 내보내고 파일 위치를 알려 주면 된다. 결과 반영과 분석은 Claude가 한다.
